# PRD – מסמך דרישות מוצר (Product Requirements Document)
**מערכת:** PropTech Multi-Agent Real Estate Investment Analyzer (מערכת מולטי-סוכנים לניתוח עסקאות והשקעות נדל"ן)
**גרסה:** 1.0.0
**מתודולוגיה:** Spec-Driven Development (SDD / OpenSpec)

---

## 1. סקירה ומטרת המערכת (Overview & Problem Statement)
משקיעי נדל"ן, שמאים ויועצי משכנתאות מבזבזים שעות על איסוף עסקאות השוואה, חישוב תמהילי משכנתא ומיסוי, וקריאת עשרות עמודים של נסחי טאבו, חוזי מכר ודוחות שמאות כדי לאתר הערות אזהרה או חריגות בנייה.

המערכת מספקת **Back End AI מרובה-סוכנים בפייתון** שמקבל כתובת נכס, מחיר מבוקש, הון עצמי וקובצי PDF של מסמכי הנכס, ומחזיר דוח השקעה מלא, מבוקר ומבוסס-נתונים.

## 2. יעדים ומדדי הצלחה (Goals & Success Metrics)
* **דיוק חישובי של 100% (Zero-Math Hallucination):** כל מדדי התשואה, המס והמשכנתא מחושבים דטרמיניסטית בפייתון ומאומתים מול סוכן מבקר (`Critic Guardrail`).
* **ציטוט מקור מחייב ב-RAG:** כל ממצא משפטי או שמאי מתוך PDF חייב לכלול מספר עמוד וציטוט מדויק מהמסמך (`exact_quote`).
* **זמן תגובה מהיר:** הרצה מקבילית אסינכרונית (`asyncio.gather`) של סוכני השוק, הפיננסים וה-RAG בפחות מ-12 שניות.
* **אפס דליפת הקשר (Zero Context Contamination):** בידוד מלא של חלון ההקשר של כל סוכן ומניעת `Context Poisoning`, `Context Clash`, `Context Distraction` ו-`Context Confusion`.

## 3. דרישות פונקציונליות (Functional Requirements)

| מזהה | שם היכולת | פירוט הדרישה |
| :--- | :--- | :--- |
| **FR-01** | **אימות JWT וניהול פרופיל משקיע מתמשך (`Long-Term Memory`)** | אימות משתמשים ב-JWT ושמירת פרופיל משקיע ב-MongoDB (הון עצמי זמין, רמת סיכון, יעד תשואה מינימלי, ערים מועדפות והיסטוריית בדיקות). |
| **FR-02** | **סוכן מחקר שוק ועסקאות השוואה (`Market & Comps Agent`)** | שליפת עסקאות אחרונות באזור הנכס, מחירי שכירות ממוצעים ונתוני שכונה מ-REST APIs חיצוניים וממסד הנתונים, וחישוב מחיר ממוצע למ"ר וסטיית המחיר המבוקש ממחיר השוק. |
| **FR-03** | **סוכן פיננסי, מיסוי ומשכנתא (`Financial & Mortgage ROI Agent`)** | הפעלת כלי פייתון דטרמיניסטיים לחישוב מדרגות מס רכישה, לוח סילוקין למשכנתא (שפיצר/קרן שווה), תזרים מזומנים חודשי נטו, תשואה ברוטו/נטו, `Cap Rate`, `Cash-on-Cash` ו-`IRR` ל-10 שנים. |
| **FR-04** | **סוכן RAG לתחקור חוזים ונסח טאבו (`Legal & Appraisal RAG Agent`)** | קליטת קובצי PDF של הנכס, פירוק סמנטי (`Loader -> Splitter -> Embedder`), אינדוקס ב-MongoDB Vector Store, וחילוץ שעבודים, עיקולים, הערות אזהרה, זכויות בנייה או סעיפים מסוכנים בחוזה. |
| **FR-05** | **סוכן בקרה ומניעת כשלים (`Risk Critic & Guardrails Agent`)** | הצלבת פלטי כל הסוכנים לזיהוי סתירות (`Context Clash` – למשל פער בין שטח הדירה במודעה לשטח בנסח הטאבו), אימות עקביות המספרים, וקביעת ציון סיכון (1–100). |
| **FR-06** | **עצירה לאישור אנושי (`Human-In-The-Loop - HITL`)** | אם ציון הסיכון עולה על הסף המוגדר או שזוהתה הערת אזהרה חריגה/תזרים שלילי, הריצה נעצרת במצב `PAUSED_FOR_APPROVAL` וממתינה לאישור או עדכון הנחות יסוד מהמשתמש דרך ה-API. |
| **FR-07** | **שרת MCP מותאם (`Custom PropTech MCP Server`)** | חשיפת כלי המערכת (תחקור DB נדל"ן, מחשבון משכנתא, שליפת ריביות וייצוא דוח) דרך שרת `FastMCP` תקני שמאפשר חיבור גם מלקוחות MCP חיצוניים. |

## 4. דרישות לא-פונקציונליות (Non-Functional Requirements)
* **NFR-01 (ארכיטקטורת שכבות):** הפרדה קשיחה של `Controllers -> BLL -> DAL`.
* **NFR-02 (אבטחה):** הצפנת סיסמאות ב-bcrypt, אימות JWT בכל נתיב עסקי, ובקרת גישה למסמכים לפי `user_id` ו-`property_id`.
* **NFR-03 (ניהול שגיאות מרכזי):** כל שגיאה במערכת מנותבת דרך `Centralized Error Manager` ומחזירה מעטפת JSON אחידה עם `trace_id`.
